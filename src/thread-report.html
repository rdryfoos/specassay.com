The Thread Report

What SpecAssay pins to every pull request.

A passing Gate proves the thread holds — but a reviewer still has to read the diff, and a green check quietly borrows credibility for everything in it. So on every PR, SpecAssay posts one briefing: what moved on the Golden Thread, the touched story walked end to end, and the changes that sit far from the thread. It illuminates; it never blocks.

A normal pull request

This walkthrough is a real PR on the bundled example app. A developer paid off some tracked debt — AC-SYNC-02, the disjoint-field merge — by adding the proof that was owed, and dropped in a small metrics module along the way. Four files changed:

tests/test_sync.pyadds test_AC_SYNC_02_… — the proofon the thread
specs/sync/tasks.mdcloses the debt task T005on the thread
src/sync.pycarries @covers AC-SYNC-02on the thread
src/metrics.pynew — event counters, no markfar from the thread

SpecAssay changes nothing about the PR itself — not its title, not its description, not its diff. It leaves the human's artifact alone and posts a comment beside it. What follows is that comment, verbatim, section by section.

Far from the thread

1 changed file sits far from the thread — it changed, but nothing in it carries a mark tying it to an intent this PR moved:
src/metrics.py

This is the whole point. metrics.py changed, but nothing in it touches an intent this PR moved. SpecAssay surfaces it for a glance — and stops there. A legitimate refactor and unwanted scope look identical from here, so the machine refuses to guess. It hands the reviewer a spotlight, not a verdict.

Why a comment, and never a block

The report never fails the build. That's doctrine, not a limitation — three postures, in increasing intervention and decreasing frequency:

  • Illuminate — always on

    The briefing above. It surfaces what's decision-relevant and renders no verdict. "Far from the thread" lives here.

  • Affirm — opt-in

    A team can set offthread_ack: required to turn the far-list into a one-click human tick before merge. That's a person's verdict, gated behind a lightweight config — never the machine's.

  • Refuse — rare, provable

    The Gate blocks only on what it can prove is a defect: a silent acceptance-criterion gap, an invented ID, exact-set drift. Off-thread is not machine-decidable as a defect, so it never earns a refusal.

The machine may only refuse what it can prove is a defect. For the rest, it makes a human look.

And it stays a comment: SpecAssay posts beside your PR, it never edits it. The diff is the record; the Thread Report is the reading glass.
